用一台 ARM 小服务器,通过 IPv6 安全回家:WireGuard + AdGuard Home 内网 DNS 折腾记 ​

记录一次完整的折腾过程:在一台只有公网 IPv6(靠 DDNS)的 Armbian 小主机上, 用 Docker 部署 wg-easy 做 WireGuard 服务端,实现外网安全访问家庭内网; 再用 AdGuard Home 提供带去广告的内网 DNS,最后借用 dpanel 的 nginx 做按域名反代, 让 http://ddns.home.inter/ 这种地址彻底不用记端口。

0. 背景与目标 ​

硬件/环境

  • 一台 ARM 小主机(arm64),系统 Armbian 26.11(Ubuntu 24.04 noble),内核 6.18。
  • 通过 IPv6 + DDNS-Go 暴露在公网,域名 vpn.home.com(只有 AAAA 记录)。
  • 内网网段 192.168.1.0/24,主机地址 192.168.1.8,网关 192.168.1.1。
  • 已跑着 dpanel(docker 面板,占 80/443)、ddns-go。
  • 只有 docker 组权限(uid 1000),没有 root 密码;root 操作需要交给本人执行。

目标

  1. 在外面(手机/笔记本)能安全访问家里内网。
  2. 尽量少暴露端口、少记端口,最好用域名搞定。
  3. 内网 DNS 能自定义域名(如 ddns.home.inter),并顺便去掉广告。

最终架构

                                   Internet (IPv6)
                                         │
                          vpn.home.com (AAAA)
                                         │
┌──────────────────────── 家庭内网 192.168.1.0/24 ────────────────────────┐
│                                                                          │
│   [客户端: Clash / WireGuard App]                                        │
│        │  UDP 51820 (IPv6)                                               │
│        ▼                                                                 │
│   小主机 192.168.1.8                                                     │
│   ├── wg-easy (host 网络) ── wg0 = 10.8.0.1/24                           │
│   │      分流:仅 192.168.1.0/24 + 10.8.0.0/24 走隧道                     │
│   ├── AdGuard Home ── DNS 192.168.1.8:53                                 │
│   │      *.home.inter → 内网 IP,其余转发上游,顺便去广告                 │
│   └── dpanel nginx (80/443) ── 按域名反代 → 各服务端口                   │
│          ddns.home.inter  → :9876                                        │
│          wg.home.inter    → :51821                                       │
│          adguard.home.inter → :3000                                      │
└──────────────────────────────────────────────────────────────────────────┘

1. 侦察:先摸清家底 ​

动手前先把环境问清楚,能避免一半的坑。

bash
# 架构 / 系统
uname -m; dpkg --print-architecture     # aarch64 / arm64

# Docker / Compose
docker --version; docker compose version

# 公网 IPv6 与内网地址
ip -6 addr show scope global
ip -4 addr show

# 端口占用
ss -ltnp; ss -lunp

# 域名解析(确认 DDNS 生效)
getent hosts vpn.home.com

几个关键结论:

  • /home/dpanel/compose 属 root,我的普通账号写不进去;
  • 但我在 docker 组里 —— 于是可以用一个一次性容器挂载 /home/dpanel 来落盘文件(等价于 root);
  • Docker 的 daemon.json 里开了 ipv6: true / ip6tables: true,所以发布端口会同时监听 [::],IPv6 入口不是问题;
  • 内网转发 net.ipv4.ip_forward=1、net.ipv6.conf.all.forwarding=1 本来已经开了;
  • WireGuard 内核模块存在(wireguard.ko)但没加载,这点后面很重要。

还有个意外的发现:ufw 其实是关闭的(ENABLED=no),而 dpanel 却能从公网访问 —— 因为 Docker 发布的端口会绕过 ufw。这条认知后面反复用到。

2. 第一站:wg-easy(WireGuard 服务端) ​

2.1 选版本:v15 是个大改写 ​

wg-easy 在 v15 做了完整重写,和网上大量 v14 教程不一样,坑点:

  • latest 标签其实还指向 v14,要显式用 :15;
  • 绝大多数环境变量没了,配置搬到 Web UI,改用 INIT_* 做无人值守初始化;
  • 需要挂载 /lib/modules 且带 SYS_MODULE,容器内才能加载 wireguard 模块;
  • HTTP 访问 UI 必须 INSECURE=true。

2.2 网络模式:为什么必须用 host ​

一开始想用 bridge + 端口映射,但访问家庭内网会翻车:

客户端 → host:51820 → DNAT 到容器 → 容器内 MASQUERADE 成容器 IP(172.x)→ 出宿主 eth0 → 内网设备看到源是 172.x,回包找不到路。

直接改成 network_mode: host:

  • WireGuard 直接用宿主机 eth0,原生支持 IPv6 入口;
  • PostUp 里的 MASQUERADE ... -o eth0 作用在真实网卡上,内网设备回包正常;
  • 代价:host 模式下不能写 ports: / sysctls:,转发参数要在宿主机上配(见第 3 节)。

2.3 编排文件 ​

/home/dpanel/compose/wg-easy/docker-compose.yml(密码放在同目录 .env):

yaml
name: wg-easy
services:
  wg-easy:
    image: ghcr.io/wg-easy/wg-easy:15
    container_name: wg-easy
    network_mode: host
    environment:
      - INSECURE=true
      - PORT=51821
      - HOST=0.0.0.0
      - INIT_ENABLED=true
      - INIT_USERNAME=admin
      - INIT_PASSWORD=${WG_ADMIN_PASSWORD}
      - INIT_HOST=vpn.home.com
      - INIT_PORT=51820
      - INIT_DNS=223.5.5.5,1.1.1.1
      - INIT_ALLOWED_IPS=192.168.1.0/24,10.8.0.0/24   # 分流
    volumes:
      - ./config:/etc/wireguard
      - /lib/modules:/lib/modules:ro
    devices:
      - /dev/net/tun:/dev/net/tun
    cap_add: [NET_ADMIN, SYS_MODULE]
    restart: unless-stopped

2.4 踩坑:ghcr.io 拉不动 / 镜像源不完整 ​

服务器在国内,ghcr.io 直连极慢,跑了十几分钟只有 "Download complete" 没有 "Pull complete";

  • 换 ghcr.nju.edu.cn/wg-easy/wg-easy:15 秒下,然后 docker tag 回标准名即可;
  • AdGuard 那会儿 Docker Hub 的 docker.1ms.run 镜像源又出现 "config descriptor not found",换 docker.1panel.live 才成功。

经验:国内拉镜像,多备几个源;拉下来的可以 retag 成标准名,compose 就不用改。

2.5 验证:真的端到端跑通 ​

不放心只看容器状态,直接调 API 建一个客户端并导出配置:

bash
# 登录拿会话
curl -s -c cj -X POST http://127.0.0.1:51821/api/auth/password \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"<PWD>","remember":false}'

# 建客户端(注意 expiresAt 必填)
curl -s -b cj -X POST http://127.0.0.1:51821/api/client \
  -H 'Content-Type: application/json' -d '{"name":"clash-rock5","expiresAt":null}'

# 导出配置
curl -s -b cj http://127.0.0.1:51821/api/client/<id>/configuration

拿到手一看,正是我们要的分流:

ini
[Interface]
Address = 10.8.0.2/32
DNS = 223.5.5.5, 1.1.1.1
[Peer]
AllowedIPs = 192.168.1.0/24, 10.8.0.0/24
Endpoint = vpn.home.com:51820

小插曲:wg-easy 的 Basic Auth 时好时坏,直接用会话 Cookie 最稳; 而且它的 API 读取重写用 /control/dns_info 之类的接口名不能想当然。

3. 第二站:用 ufw 给"裸奔"的主机穿上衣服 ​

既然 ufw 是关的、Docker 又绕过 ufw,那这次顺手把该开的开、该关的关。写成一个 root 脚本 firewall-root.sh(需要真正 root,交给本人 sudo bash 执行)。

要点:

  1. 持久化转发参数:

    ini
    # /etc/sysctl.d/90-wireguard.conf
net.ipv4.ip_forward=1
net.ipv4.conf.all.src_valid_mark=1
net.ipv6.conf.all.forwarding=1
net.ipv6.conf.default.forwarding=1

  2. 放行:

    ufw allow 22/tcp                 # SSH(别把自己关外面)
ufw allow 51820/udp              # WireGuard
ufw allow from 192.168.1.0/24    # 局域网整段
ufw allow in on wg0              # VPN 客户端
ufw allow from 172.16.0.0/12     # Docker 容器 -> 宿主机服务
ufw allow from fd00::/8          # 同上(IPv6)

  3. 转发规则(否则 default deny routed 会把 VPN 转发全 drop):

    ufw route allow in on wg0 out on eth0
ufw route allow in on eth0 out on wg0
ufw route allow in on wg0 out on wg0

  4. 最后重启 wg-easy 容器,让它的 iptables/NAT 规则重新写入。

一个诊断教训 ​

我一度用 docker run --privileged -v /:/host ... chroot /host ufw status 去查状态, 结果报 "inactive"。原因是我忘了加 --net=host —— 容器有自己的网络命名空间, 看到的 iptables 是空的。加上 --net=host 才是宿主机的真实规则。

教训:在容器里查宿主机网络状态,必须 --net=host,否则看到的是假象。

4. 第三站:AdGuard Home —— 内网 DNS + 去广告 ​

4.1 那个绕不过的 53 端口 ​

宿主机 systemd-resolved 占着 127.0.0.53:53 和 127.0.0.54:53。 如果 AdGuard 绑 0.0.0.0:53 会 EADDRINUSE。

最省事的解法:让它只绑定内网口 192.168.1.8:53,既避开冲突,又不用动系统配置。

yaml
name: adguardhome
services:
  adguardhome:
    image: adguard/adguardhome:latest
    container_name: adguardhome
    network_mode: host
    volumes:
      - ./work:/opt/adguardhome/work
      - ./conf:/opt/adguardhome/conf
    restart: unless-stopped

安装向导用 API 跑,把 DNS 监听地址指定成内网口:

bash
curl -s -X POST http://127.0.0.1:3000/control/install/configure \
  -H 'Content-Type: application/json' \
  -d '{"web":{"ip":"0.0.0.0","port":3000},
       "dns":{"ip":"192.168.1.8","port":53},
       "username":"admin","password":"<PWD>"}'

4.2 自定义内部域名(DNS 重写) ​

在「过滤器 → DNS 重写」里加,或用 API:

bash
curl -s -b cj -X POST http://127.0.0.1:3000/control/rewrite/add \
  -H 'Content-Type: application/json' \
  -d '{"domain":"ddns.home.inter","answer":"192.168.1.8"}'
域名指向
router.home.inter192.168.1.1
ddns.home.inter192.168.1.8
wg.home.inter192.168.1.8
dpanel.home.inter192.168.1.8
adguard.home.inter192.168.1.8

然后把 wg-easy 下发给客户端的 DNS 改成 192.168.1.8(管理员 → User Config → DNS), 新客户端就会自动带上内网 DNS。

4.3 去广告 ​

新装的 AdGuard 默认没有下载任何规则(rules_count=0),要手动触发:

bash
curl -b cj -X POST http://127.0.0.1:3000/control/filtering/refresh \
  -H 'Content-Type: application/json' -d '{"whitelist":false}'
  • 默认「AdGuard DNS filter」≈ 18.4 万条;
  • 再加中文规则「anti-AD」(https://anti-ad.net/easylist.txt)≈ 9.5 万条。

验证:

bash
nslookup doubleclick.net 192.168.1.8     # → 0.0.0.0,拦了
nslookup www.qq.com 192.168.1.8          # → 正常解析
nslookup ddns.home.inter 192.168.1.8     # → 192.168.1.8

小插曲:批量加规则时用 shell 循环 set -- $pair 结果全 400。 因为当前 shell 是 zsh,默认不对未加引号的变量做分词,$pair 整个当成一个参数拼出了非法 JSON。 改成显式命令或用 bash 跑就正常了。

5. 第四站:免端口访问 —— 借 dpanel 的 nginx 按域名反代 ​

目标:访问 http://ddns.home.inter/(80 端口),不用写 :9876。

难点:宿主机的 80/443 已经被 dpanel 的 nginx 占了。既然它本来就是个反代管理器,直接用它:

  • dpanel 的 nginx.conf 里有 include /dpanel/nginx/proxy_host/*.conf;,对应宿主机 /home/dpanel/nginx/proxy_host/;
  • 里面本来就有个 default_server,返回 404 兜底 —— 我们只要加带 server_name 的 vhost 即可。

给每个域名写一个 vhost(手工添加,dpanel 未纳管):

nginx
# /home/dpanel/nginx/proxy_host/10-internal-ddns.home.inter.conf
server {
    listen 80;
    listen [::]:80;
    server_name ddns.home.inter;

    allow 192.168.1.0/24;   # 只有内网/VPN 能进
    allow 10.8.0.0/24;
    deny all;

    location / {
        proxy_pass http://192.168.1.8:9876;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
    }
}

重载:

bash
docker exec dpanel nginx -t && docker exec dpanel nginx -s reload

又一个坑:dpanel 容器够不到宿主机服务 ​

配好后 curl 全 000。查出来是 dpanel 容器(源 172.x)访问宿主机 host 网络上的服务, 被 ufw 的 INPUT 默认策略挡了(之前只放行了 192.168.1.0/24 和 wg0)。

补一条即可(已并入 firewall-root.sh):

bash
ufw allow from 172.16.0.0/12
ufw allow from fd00::/8

补完立刻全通:ddns 307 / wg 302 / adguard 302 / dpanel 200。

6. 日常维护:以后要新增内网域名 / DNS 规则怎么加 ​

再强调那个最容易被误解的点:DNS 只负责「名字 → IP」,不包含端口。 所以新增一个域名分两种情况:

情况要做的事
服务本来就在 80 端口只加一条 DNS 重写
服务在别的端口(如 :5000),想连端口都不写DNS 重写 + 一个 80 端口反代 vhost

方式一:面板点(最简单) ​

AdGuard → 过滤器 → DNS 重写 → 添加

  • 域名:nas.home.inter
  • 答案:192.168.1.5
  • 保存即立即生效(不用重启)。

这只解决"名字→IP";若服务在 :5000,访问仍要写 http://nas.home.inter:5000/。

方式二:脚本(连端口一起省) ​

在 adguardhome 目录下我放了个 add-internal-domain.sh:

bash
# 语法: add-internal-domain.sh <域名> <IP[:端口]>
bash /home/dpanel/compose/adguardhome/add-internal-domain.sh nas.home.inter 192.168.1.5        # 服务在 80
bash /home/dpanel/compose/adguardhome/add-internal-domain.sh nas.home.inter 192.168.1.5:5000   # 自动加反代

它做的事 = 加 DNS 重写 + 写 /home/dpanel/nginx/proxy_host/10-internal-<域名>.conf + reload nginx; 之后 http://nas.home.inter/ 直达 :5000。

方式三:纯命令 ​

bash
# 1) 登录拿会话
curl -s -c /tmp/ag.c -X POST http://127.0.0.1:3000/control/login \
  -H 'Content-Type: application/json' -d '{"name":"admin","password":"<密码>"}'

# 2) 加 DNS 重写
curl -s -b /tmp/ag.c -X POST http://127.0.0.1:3000/control/rewrite/add \
  -H 'Content-Type: application/json' -d '{"domain":"nas.home.inter","answer":"192.168.1.5"}'

# 3) 验证
nslookup nas.home.inter 192.168.1.8

删除 / 修改 ​

  • DNS 重写:在面板里删即可。
  • 反代:改或删对应的 vhost 文件,然后重载:
    bash
    docker exec dpanel nginx -t && docker exec dpanel nginx -s reload

几个注意点 ​

  • 持久化:面板/API 改的都写进 conf/AdGuardHome.yaml,重启容器也还在。
  • 反代访问范围:脚本生成的 vhost 默认 allow 192.168.1.0/24; allow 10.8.0.0/24; deny all;,公网访问 403。
  • 拦截/去广告规则:在 过滤器 → DNS 黑名单 填 URL,或 自定义过滤规则 写单条(如 ||ads.example.com^),加完点「检查更新」下载。
  • 泛解析:要的话在重写里用 *.home.inter,但那样所有名字都指向同一台机器,只有服务都在这台上时才好用。

7. 客户端:Clash(WireGuard 出站)配置 ​

Mihomo/Clash.Meta 支持 WireGuard 出站。关键:wg-easy 的客户端带了 PSK,必须一起填,否则握手必失败。

yaml
proxies:
  - name: rock5-wg
    type: wireguard
    server: vpn.home.com
    port: 51820
    ip: 10.8.0.2/32
    private-key: "<CLIENT_PRIVATE_KEY>"
    public-key: "<SERVER_PUBLIC_KEY>"
    pre-shared-key: "<PSK>"
    allowed-ips:
      - 192.168.1.0/24
      - 10.8.0.0/24
    dns:
      - 192.168.1.8
    remote-dns-resolve: true
    persistent-keepalive: 25
    mtu: 1420
    udp: true

proxy-groups:
  - name: PROXY
    type: select
    proxies: [rock5-wg, DIRECT]

rules:
  - DOMAIN-SUFFIX,home.inter,rock5-wg
  - IP-CIDR,192.168.1.0/24,rock5-wg,no-resolve
  - IP-CIDR,10.8.0.0/24,rock5-wg,no-resolve
  - MATCH,DIRECT
  • allowed-ips 决定"哪些目的地走隧道"(分流);
  • dns + remote-dns-resolve 让 *.home.inter 通过隧道的 AdGuard 解析;
  • IP-CIDR ... no-resolve 保证按 IP 访问内网也走隧道。

只有 AAAA 记录,所以客户端所在网络必须支持 IPv6。

10. 总结 ​

  • WireGuard 本身足够安全(Noise 协议),套 TLS 并不会让隧道"更安全";证书只对"直接暴露公网的服务"有价值。内网这套走 HTTP 完全够。
  • IPv6-only + DDNS 是低成本暴露家庭网络的好方式,代价是客户端网络也得有 IPv6。
  • host 网络是容器化 VPN/内网访问的关键选择,bridge 的回程 NAT 会让人怀疑人生。
  • DNS 和反代是"少记端口"的两把钥匙:DNS 把名字指到 IP,反代把名字指到端口。
  • Docker 绕过 ufw 既是便利也是隐患,配 host 网络服务时要心里有数。

整个折腾下来,最终体验是:在外面连上 WireGuard,浏览器里敲 http://ddns.home.inter/ 就能打开家里的服务——没有端口、没有证书警告,而且全家上网都顺手清了广告。
